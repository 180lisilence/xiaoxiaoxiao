# 内网穿透配置指南（SakuraFrp）

> 适用于 小笑肖 v4.0.2 · 手机不在家里 Wi-Fi 时怎么连上电脑后端

---

## 先说结论：你现在这条隧道跑不通

你当前这条隧道是 **`gzt` → `frp-gap.com:56974`**，实测结果：

| 测试 | 结果 | 含义 |
|---|---|---|
| `http://frp-gap.com:56974/api/ping` | **501** | Sakura 节点拦下了明文 HTTP 请求 |
| `https://frp-gap.com:56974/api/ping` | **握手失败** | TCP 隧道不做 TLS 终结，节点没有证书 |

Sakura 返回的 501 页面上写得很清楚：

> 您正试图使用 HTTP 协议访问此隧道
> 因为下面的原因，此请求已被拦截：执行机房的内容合规要求和有关部门的管控规定

**根本原因（Sakura 官方文档明确规定的）：**

> 根据有关规定，使用 `TCP` 隧道时，如果您穿透的**应用协议是 HTTP，必须使用非内地节点**

你选的 `yd.frp-gap.com` 是 **41 号节点（内地）**。内地 TCP 隧道跑 HTTP 应用，
节点层面就会拦掉。这不是配置错，是政策限制，怎么调都过不去。

---

## 三条可走的路（任选一条）

### 方案 A · 换非内地 TCP 节点（最简单，推荐先试）

**可行原因**：只改节点，隧道类型还是 TCP，不用备案、不用域名。

1. 打开 SakuraFrp 面板 → 隧道列表 → 编辑 `gzt`
2. **节点** 改成**非内地节点**（香港 / 日本 / 新加坡 / 美国等，面板上标注「海外」或「境外」）
3. **本地端口** 改成 **`8731`**（这是你启动器实际监听的端口，原来那个 25565 是别的服务）
4. 保存 → 重启隧道
5. 记下新的公网地址（形如 `cn-hk-xxx.natfrp.cloud:12345`）
6. 手机端「连接电脑」填：**新地址:端口**，**不要**带 `http://`

**电脑端启动器**：不用勾 HTTPS。

---

### 方案 B · 新建 HTTP 类型隧道 + 自动 HTTPS（最稳，但要域名）

**可行原因**：HTTP 隧道由 Sakura 节点代持证书，手机端拿到的是受信任的证书，
不会有任何警告，也绕过了内地节点跑 HTTP 的限制。

1. 面板新建隧道 → 隧道类型选 **`HTTP`** 或 **`HTTPS`**（不是 TCP）
   - 节点必须带绿色「**建站**」标识
   - **内地节点需要域名已备案**；没有备案域名就选**非内地建站节点**
2. 绑定域名：可以用 Sakura 送的子域名（如 `xxx.natfrp.cloud`），也可以用自己的域名
3. 本地 IP `127.0.0.1`，本地端口 **`8731`**
4. 如果想用 HTTPS：在隧道编辑页把「**自动 HTTPS**」设为 `自动`
5. 按面板提示配置 CNAME 解析
6. 手机端填 **`https://你的域名`**（HTTP 隧道不需要带端口）

**电脑端启动器**：这条方案下**不要**勾「启用 HTTPS」——
节点是用明文 HTTP 来连你本机的，你开了 HTTPS 反而会握手失败（文档里的「TLS 套 TLS」问题）。

---

### 方案 C · 内地 TCP 隧道 + 电脑端自己上 HTTPS

**这条就是你刚才那条隧道想走的路，但 Sakura 的 TCP 隧道不支持 TLS 透传，实测走不通。**
留着备查，不推荐。

新版启动器已经支持「启用 HTTPS」开关（自签证书自动生成），
在**非内地节点**上如果遇到「要求 HTTPS」的节点策略，可以打开它、手机端地址带 `https://`。

## 逐项配置对照表

| 项目 | 方案 A（非内地 TCP） | 方案 B（HTTP 隧道） |
|---|---|---|
| 隧道类型 | `TCP` | `HTTP` 或 `HTTPS` |
| 节点 | **非内地**（关键） | 带「建站」标识；内地需备案域名 |
| 本地 IP | `127.0.0.1` | `127.0.0.1` |
| 本地端口 | **`8731`** | **`8731`** |
| 自动 HTTPS | 关 | 按需开 |
| 启动器「启用 HTTPS」 | **不勾** | **不勾** |
| 手机端填什么 | `域名:端口` 不带协议 | `https://域名` 不带端口 |

## 最容易踩的 4 个坑

1. **本地端口写成 25565**
   这是你之前那条 Minecraft 隧道的端口。工作台后端监听的是 **8731**，
   填错会得到「连接被拒绝，目标端口可能未打开」。

2. **内地节点 + TCP + 明文 HTTP**
   必回 501。要么换非内地节点，要么换 HTTP 隧道类型。

3. **隧道「建好了」但没「启动」**
   面板里看到隧道存在不等于在跑。看客户端日志出现
   `TCP 隧道启动成功` 和 `使用 >>xxx<< 连接你的隧道` 才算启动。

4. **电脑端启动器没点「启动服务」**
   启动器没运行 = 本机 8731 没有进程监听 = 隧道转发到哪里都没人接。
   必须在启动器上看到「● 运行中」绿灯。

## 自检清单（按顺序打勾）

- [ ] 启动器打开，显示「● 运行中」
- [ ] 电脑浏览器打开 `http://127.0.0.1:8731/api/ping` 能看到 `{"ok": true, ...}`
- [ ] 隧道客户端日志里有「隧道启动成功」
- [ ] 隧道的本地端口 = 8731
- [ ] 手机和电脑**不在同一 Wi-Fi** 时，用手机浏览器打开穿透地址能返回内容
- [ ] 手机 App 里填的地址与上面完全一致（协议 / 域名 / 端口）

## 本次已完成的后端改动（v4.0.2）

| 改动 | 为什么 |
|---|---|
| 后端支持 HTTPS（`start(tls=True)`） | 部分穿透方案要求源站是 HTTPS |
| 自签证书自动生成（数据目录 `server.crt` / `server.key`） | 省去手动申请证书 |
| 启动器加「启用 HTTPS」开关 | 不用改配置文件，界面上点 |
| 手机端放行自签证书（`onReceivedSslError`） | 否则 WebView 直接取消请求，表现为「连不上但无报错」 |
| 工作台自动识别后端是 HTTP 还是 HTTPS | 原来写死 `http://`，开了 TLS 就打不开 |
| 连接失败排查清单重写 | 把 501 / 端口错 / 隧道类型错都写进提示 |
